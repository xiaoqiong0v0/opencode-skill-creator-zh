# ASYNC 变更说明（2026-10-29）

## 新增 `docs/ASYNC.md`：eval / optimize 并发交互点清单

**原来**：仓库没有项目级异步清单；`eval` / `optimize` 的并发契约只散落在 `run-eval.ts` 的注释与测试里，评审与后续改动没有统一入口可查——「多 worker 怎么收集结果、哪些状态共享、取消怎么传播」只能靠读代码推断。

**现在**：新建 `docs/ASYNC.md`，按四要素（共享状态 · 保护手段 · 顺序契约 · 位置）登记 7 个交互点：多 worker 结果收集、`opencode` 子进程池、`evalRoot` 生命周期、deny 配置写入时机、报告与日志落盘、取消信号传播、调试输出；末尾附「可失败断言」门禁表，每条交互点都能指到具体 `src/` 函数与一条测试。

**为什么**：B4 引入了并发（`--workers`）、子进程池、临时目录与取消信号，任何一处顺序写错都会表现为「偶发假阴性 / 临时目录残留 / 报告互相覆盖」。把隐性契约写进项目文档并在测试里钉住，才能在下一次改动时被检查到；这也是 ROADMAP B4「同批产出 `docs/ASYNC.md`」的落地。

## 并发清单随 B4 复核同步（同日第二批）

**原来**：清单写「枚举可见技能在所有 query 之前只做一次」、报告写单层 `<logDir>`、deny 固定写 `opencode.json`，也没有登记「隔离准备失败中止整轮」这条新的失败路径。

**现在**：改为「每次 `runEval` 调用枚举一次（`optimize` 每轮各一次）」；报告改为 `eval` 单文件 + `optimize` 独立运行子目录；deny 改为「jsonc 优先、否则新建 json」；§1 共享状态补 `fatalError` 与「整轮中止、不产出报告」；§2 补改善子进程共用 `--timeout`；§8 门禁表补 J4 三条与 optimize 运行子目录断言。

**为什么**：清单必须与实现同步，否则「按清单排查」会指向错误的文件与时机；`fatalError` 是这次复核新增的关键并发契约（失败不能被 worker 吞成单条错误），漏登记就等于没修。
