# 技能评测隔离问题 变更说明（2026-10-29）

## 坑 B 的「正确做法」定稿为「`directory` → `worktree` → 报错」（同日第二批）

**原来**：坑 B 的「正确做法」写「项目根只能来自调用方传入的 instance root（`ctx.location.directory` 一类）；确需 fallback 时必须限定边界（不越过 worktree 根，或最多向上 N 层），且输出实际命中的根」，另加「排除运行时目录」「校验项目形态」两条。验收方式里第一个用例就是「以 `A/B/work` 调用取根函数，断言返回 `A`」——即默认向上找是主路径；还带一条「不超过 N 层」的用例。

**现在**：定稿为固定优先级 `ToolContext.directory`（首选，所有相对路径的基准）→ `worktree`（次选）→ 三段式报错 `错误：拿不到当前项目目录` / `改法：在 opencode 会话内重试，或显式传绝对路径`。**`process.cwd()` 与向上查找一律禁止**；向上查找降级为「仅独立 CLI 场景（拿不到 `ToolContext`）的兜底」，且必须 ① 排除 `~/.opencode`、`~/.config/opencode`；② 校验项目形态；③ 打印实际命中的根与来源。验收方式改写为五条：分发层透传（已在 B2 落地，`test/dispatch-context.test.js`）、兜底路径的祖先命中用例（限定只在无 `ToolContext` 时生效）、`process.cwd` 打桩、home 下临时目录的实证用例、非项目形态候选根不采纳；删掉「N 层上限」用例。文末 J2 汇总条目同步。

**为什么**：`N` 层上限是无依据的魔数，且与「不向上找」的目标相反；真正需要守的是「根不许由 cwd 派生」。B2 已把 `ToolContext` 透传到 `dispatch`，优先级因此可以写死成可验收的三档，兜底只留给没有 `ToolContext` 的独立 CLI 场景——这也和用户实测的「子目录/临时目录里跑评测用了错根」直接对上。
