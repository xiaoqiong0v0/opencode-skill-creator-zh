# 变更说明：技能正文的 `new` / `validate` 口径与评测集骨架

日期：2026-10-30

**原来**：`skill/SKILL.md` §8 的工具表把 `skill_zh new` 写成「生成 `SKILL.md` + `references/`」、把 `validate` 写成「校验结构与 frontmatter」；§4.3 让作者「草稿完成后写 2–3 条测试 prompt」，没提 `new` 已经带了骨架。

**现在**：

1. §8 表格：`new` 补「+ 可直接跑的最小 `eval_set.json`；`--force` 不覆盖已有评测集」；`validate` 补「含 description 占位文案；`--strict` 把提示升级为错误」。
2. §4.3 补一句：`skill_zh new` 建的技能已有 2 正 1 负骨架，直接替换占位 `query` 即可（多余字段会被忽略）。

**为什么**：技能正文是模型执行流程时唯一会读的规范，正文写着「先手写评测集」而工具已生成骨架，会让模型多走一步；`--strict` 的占位判据不写进正文，模型就不知道「骨架原样不能算完成」。工具名、子命令与错误格式属被依赖的约定，改动须留痕。
