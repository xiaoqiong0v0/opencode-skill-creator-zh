# 技能打包决策 变更说明（2026-10-29）

## 配套约束 3、4 的口径调整

**原来**：

- 约束 3：写入范围只在 `~/.config/opencode/skills/opencode-skill-creator-zh/` 内；
- 约束 4：升级时保留用户对 `SKILL.md` 的改动并**备份为同目录下的 `SKILL.md.user-backup`**。

**现在**：

- 约束 3：写入范围 = 自己的技能目录 + `~/.config/opencode/skills/.skill-zh-state/`（安装状态），仍不碰其它技能目录与 `.claude/`、`.agents/`；
- 约束 4：`SKILL.md` 与状态文件记录的哈希不一致时**默认不覆盖**，提示 `--force`；备份写状态目录、带时间戳，不写进技能目录。

**为什么**：同目录备份属于「安装器元数据污染技能目录」，会让「技能目录内容 = 技能本体」失效，并使 `skill_zh package` 的导出内容不确定；「备份后覆盖」则每次升级都吃掉用户改动。新的 `SPEC R6.1` 已把这两点定为可判定要求（I2、I5），本决策的配套约束必须与之一致。详见 [../design/技能安装与目录问题.md](../design/技能安装与目录问题.md)。
