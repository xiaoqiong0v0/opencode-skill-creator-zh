# 变更说明：子命令参考补 shell 等价入口与独立 CLI 目录口径

日期：2026-10-30

**原来**：tools.md 只描述 OpenCode 工具 `skill_zh` 的调用方式；「路径解析基准」写「仅独立 CLI 场景才允许兜底向上查找，并排除 `~/.opencode` / `~/.config/opencode`」，但仓库当时并没有独立 CLI。

**现在**：

1. 「通用约定」新增两行：`shell 入口`（`skill-zh` bin 复用子命令；argv 按 token 解析；成功 stdout / 0、失败 stderr / 1）与 `shell 目录基准`（cwd 即项目目录、不向上查找；配置目录 cwd 警告但继续）。
2. 7 个子命令各加一行 `shell 等价：skill-zh <子命令> …`。
3. 「路径解析基准」的硬口径改为：插件与分发层不读 cwd；独立 CLI 只把 cwd 当项目目录、同样不向上查找。

**为什么**：用户需要在 shell 里直接查到每条工具调用的等价命令；同时「允许向上查找」的旧表述已与新 bin 的实际行为不符，留着会误导。

**2026-10-30 复核收口**：shell 输出里的 `skill_zh` 会归一成 `skill-zh`，示例与三段式可直接照抄；「独立 CLI 向上查找」旧口径的残留段落已改为 cwd 即根、不向上查找。

## 2026-10-30 追加：`new` 生成评测集骨架、`validate` 认占位、`package` 放宽 `references/`、eval 汇总区分口径

**原来**：`new` 只写 `SKILL.md` + `references/示例.md`，新技能第一次 `eval` 必报「评测集不存在」；`validate --strict` 只认长度与命名，模板骨架的占位 description 仍判通过；`package` 要求 `references/` 存在才允许导出；eval 汇总写「触发率均值 x.xx ± y.yy」，与通过率并列时容易被读成得分。

**现在**：

1. `new` 增加 `eval_set.json`（2 正 1 负、可直接跑，`_comment` 写改法）；`--force` 重写 `SKILL.md` / `references/示例.md` 并留 `.bak`，**已存在的评测集一律保留**；输出与「下一步」列出三样产物。
2. `validate` 新增**提示**级问题「description 仍是占位文案」，判据**只认占位形态**：开头 `TODO:` / `待填:`（半角或全角冒号、大小写不敏感）或整体等于模板占位原文；中间出现 `TODO` / `待填` 不报（`管理 TODO 清单`、`处理等待填写的审批表单` 属于合法文案）。`--strict` 升级为错误，`new` 骨架原样在 `--strict` 下必然失败。文档补缺省 / strict 两份示例与反例。
3. `package` 的 `references/` 改为可选（白名单与 `SKILL.md`、name 一致性检查不变），自检行改为「只导出白名单内容」。
4. eval 汇总主行与极性分组行统一为 `原始触发率 x.xx ± y.yy（诊断用，非通过率）`，并补一张「两种数字口径」表；示例数字按实际算法对齐（不再出现与条目不符的 ±0.71）。

**为什么**：真机反馈「新技能第一次评测必失败」「`--strict` 对模板骨架形同虚设」「简单技能没法打包」「触发率被读成通过率」。四条都是用户第一公里体验，且都不改命令形态，只在既有子命令上补默认值与判据。

**2026-10-30 复核收口**：占位判据最初按「含 `TODO` / `待填` 子串」实现，复核发现会把 `管理 TODO 清单`、`处理等待填写的审批表单` 这类合法 description 在 `--strict` 下判死，已收紧为「**开头** `TODO:` / `待填:`（半角或全角冒号、大小写不敏感）或**整体等于**模板占位原文」，中间出现一律不报；同批补 2 条反例用例，`tools.md` 的判据段落改为写明「不是含 TODO」。另：`help` 的 `new` 行补「`eval_set.json` 始终不覆盖」，`new` 的「下一步」不再写死 query 条数（保留旧评测集时条数不同）；`eval` 汇总口径表补「不应触发组越低越好」。
