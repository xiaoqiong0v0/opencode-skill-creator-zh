# 决策：技能随 npm 包分发（入包）

[文档索引](../README.md) · [需求与验收](../SPEC.md)

## 背景

本插件交付的是「技能创建工具」：工具负责新建、校验、评测、优化与打包技能，而**工具自己也需要一套技能正文**（`SKILL.md` + `agents/` + `references/` + `templates/`）告诉模型什么时候用、按什么流程走。问题是这套正文怎么交付：

- **入包**：正文放在 npm 包里（`skill/` 目录），插件加载时安装到用户级技能目录；
- **不入包**：npm 包只带代码，技能正文由用户/agent 另行获取（手动复制、独立仓库、或启动时联网下载）。

## 两种做法对比

| 维度 | 入包 | 不入包 |
|---|---|---|
| 安装步骤 | 一步：装包即得工具 + 技能 | 两步：装包 + 另取技能正文，容易只做一半 |
| 版本一致性 | 技能与代码同一版本号，天然对齐 | 两侧独立演进，出现「新工具 + 旧正文」的概率高 |
| 离线可用 | 装完即可用 | 需要联网或手工搬运 |
| 与上游英文技能共存 | 靠目录名区分即可（`-zh` 后缀） | 同样靠目录名，但用户手工放置更容易放错/覆盖 |
| 包体积 | 增大（正文 + 模板，几十 KB 量级） | 最小，但换来的是每次手工装配 |
| 正文改动与代码发版 | 耦合：改正文要发版 | 解耦：正文可独立改 |
| 可发现性 | OpenCode 启动即按目录名发现 | 依赖用户放对路径 |
| 维护成本 | 一次设计安装/升级/清理逻辑 | 无安装逻辑，但把成本转嫁给每个用户 |

## 结论

**入包**。npm 包内只保留唯一一份技能目录 `skill/`，与 `dist/` 平级；插件加载后装到 `~/.config/opencode/skills/opencode-skill-creator-zh/`，与上游英文技能（`opencode-skill-creator/`）共存。

## 四条理由

1. **单工具理念的完整交付**：工具收敛成 1 个的前提是「模型知道什么时候用它、按什么流程走」，这件事只能由技能正文承担。正文不入包，等于把工具的一半作用留给用户装配。
2. **版本一致性可验证**：正文与代码同版本号，`npm pack` 一次即可核对「代码 + 正文」是否成套；不入包时没有任何机制保证两侧匹配，而正文与子命令名强耦合（正文里写错子命令名，模型就会调用失败）。
3. **共存靠命名而非约定**：目录名 = 插件 id = frontmatter `name`，三者一致的 `-zh` 后缀使本包与上游英文技能互不覆盖；不入包时目录名由用户决定，冲突只能靠文档提醒。
4. **升级/回滚可审计**：「只写自己的目录」「升级保留用户 `SKILL.md` 改动并备份」这类约束，只有在我们控制安装器时才成立；不入包则完全依赖用户手工操作，无法给出可执行的验收断言。

## 配套约束（缺一不可）

入包带来的耦合，用下面四条约束把它压住：

1. **包内容收敛**：`files: ["dist", "skill", "README.md"]`，源码与测试不入包；`npm pack --dry-run` 必须能核对到这一点。
2. **三处命名一致**：技能目录名、插件 id（`opencode-skill-creator-zh`）、frontmatter `name` 完全一致，否则 OpenCode 发现不到技能，或与上游技能互相覆盖。
3. **写入范围受限**：安装/升级/清理只在 `~/.config/opencode/skills/opencode-skill-creator-zh/`（技能本体）与 `~/.config/opencode/skills/.skill-zh-state/`（安装状态）内进行，不触碰其它技能目录（含上游 `opencode-skill-creator/`，也不动 `.claude/`、`.agents/`）。
4. **正文改动可留存**：`SKILL.md` 与状态文件记录的哈希不一致（= 用户改过）时升级**默认不覆盖**，提示 `--force`；备份写状态目录、带时间戳，不写进技能目录（取代上游的「同目录 `SKILL.md.user-backup` + 备份后覆盖」）。正文的关键结构（子命令名、错误格式、安装路径）变更必须在 `docs/changes/` 留痕，因为正文与代码是强耦合的。详见 [技能安装与目录问题.md](技能安装与目录问题.md)。

## 对验收的影响

| 验收项 | 依赖本决策的地方 |
|---|---|
| SPEC R6 | 包内唯一一份技能、安装路径、与上游共存 |
| SPEC R7 | `npm pack --dry-run` 核对包内容 |
| ROADMAP B5 | 安装器只在目标目录内写/删 |
| ROADMAP B6 | 正文里的 `skill_*` 旧名改写，改完须与 `HELP_TEXT` 对齐 |

## 未采纳方案

- **独立技能仓库 + 手动安装**：多一步装配，且无法保证与包版本匹配（否决理由 2）。
- **启动时联网下载正文**：引入网络依赖与供应链风险，离线不可用，且失败时工具静默缺一半能力。
- **正文直接写进代码字符串**：正文与模板要能被 agent 直接读取（`references/`、`templates/eval-review.html` 有独立文件语义），塞进代码会让「按需加载」失效。
