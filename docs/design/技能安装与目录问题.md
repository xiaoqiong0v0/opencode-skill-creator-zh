## 背景

「把技能装进去」看起来只是拷一个目录，实际有三层约束叠在一起：

- **发现层**：OpenCode 不止扫 `~/.config/opencode/skills` 一处，还存在 `.claude` / `.agents` 等外部目录，且后扫描的同名技能会覆盖先扫描的。装对位置不等于生效。
- **安装层**：安装器自己会往目标技能目录里写元数据（版本标记、manifest、备份），会让「技能目录内容 = 技能本体」这个直觉失效，也让升级/清理逻辑互相纠缠。
- **升级层**：用户改了 `SKILL.md` 之后重装会怎样，取决于安装器是「备份后覆盖」还是「有改动就不动」；上游选前者，代价是用户的改动被覆盖。

上游安装器在发现层完全不做检测，在安装层把元数据写进技能目录，在升级层只做备份后覆盖。三条都是本仓要改掉的。下面 6 条是据此整理的问题清单，每条给出可验证的验收方式，末尾汇总成对实现的约束。

## 事实底座

### 一、技能发现源（opencode v1.18.25 `packages/opencode/src/skill/index.ts`）

常量（`:21-25`）：

| 常量 | 值 |
|---|---|
| `CLAUDE_EXTERNAL_DIR` | `.claude` |
| `AGENTS_EXTERNAL_DIR` | `.agents` |
| `EXTERNAL_SKILL_PATTERN` | `skills/**/SKILL.md` |
| `OPENCODE_SKILL_PATTERN` | `{skill,skills}/**/SKILL.md` |

按**扫描顺序**列出（`:185-227`），同名技能以**最后扫描到的为准**：

| 序 | 来源 | 规则 | 关闭方式 | 源码 |
|---|---|---|---|---|
| 1 | 外部 `.claude` | `~/.claude/skills/**/SKILL.md` 及项目逐层同路径（`:187` 显式纳入） | `OPENCODE_DISABLE_EXTERNAL_SKILLS`（总开关）；或 `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`、`OPENCODE_DISABLE_CLAUDE_CODE` | `:185-203`、`:21-25` |
| 2 | 外部 `.agents` | `~/.agents/skills/**/SKILL.md` 及项目逐层同路径 | 只受 `OPENCODE_DISABLE_EXTERNAL_SKILLS` 控制（关掉它是唯一开关） | `:185-203` |
| 3 | OpenCode 自有配置目录 | `~/.config/opencode/{skill,skills}/**/SKILL.md` | — | `:205-208` |
| 4 | `skills.paths` 配置项 | 配置里列出的目录 | — | `:211-219` |
| 5 | `skills.urls` 配置项 | 配置里列出的远程地址 | — | `:222-227` |

外部目录的扫描范围包括**用户级** `~/.claude`、`~/.agents`，以及「**从当前工作目录向上到 worktree 根**」的每一层（`:185-203`）。用户级 `.claude` 确在扫描范围内：`:187` 的 `if (!disableClaudeCodeSkills) externalDirs.push(CLAUDE_EXTERNAL_DIR)` 把 `.claude` 显式加入外部目录列表，只受 `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` / `OPENCODE_DISABLE_CLAUDE_CODE` 控制（**跨版本仍建议复核**）。探测逻辑按「用户级 + 项目逐层」两段写。

第 3～5 项的文件名匹配是 `{skill,skills}/**/SKILL.md`，也就是说 `skills/` 下**任意层级**都有 `SKILL.md` 才会被发现，没有「只扫一层」的限制。

## 六条坑

### 1. 拷贝范围失控：传错目录就把开发产物搬进技能目录

- **现象**：安装后技能目录里出现 `dist/`、`bin/`、`test/`、`node_modules/`、`.git/` 之类与技能无关的内容；轻则技能目录体积暴涨，重则模型按需加载时读到构建产物。
- **根因**：`copyDirRecursive`（`.tmp/old/plugin/lib/skill-install.ts:74-85`）对源目录**没有任何白名单**，`readdirSync` 出来什么就拷什么；`RESERVED_ROOT_PATHS`（`:36-57`）保护的是**目标侧不被删除**，与「拷什么进来」无关。
- **正确做法**：**白名单拷贝**。只允许顶层 `SKILL.md` 与目录 `agents/`、`references/`、`templates/`；白名单外的条目**跳过**，并在 `SKILL_ZH_DEBUG=1` 时告警一条（常态化静默，避免噪声）。白名单本身提为常量，只留一处实现。
- **验收方式**：构造一个源目录，除白名单四项外再放 `dist/`、`bin/`、`test/`，跑安装；断言目标技能目录内**不存在** `dist/`、`bin/`、`test/`，且白名单四项逐文件与源一致。

### 2. 安装器元数据污染技能目录

- **现象**：技能目录里混进 `.opencode-skill-creator-version`、`.opencode-skill-creator-manifest.json`、`SKILL.md.user-backup`；用户分不清哪些是技能本体，卸载时也不敢整个删；`skill_zh package` 若照抄目录，会把元数据一起导出。
- **根因**：元数据被设计成「写在技能目录内」，见 `:19`（版本标记）、`:27`（manifest）、`:324`（备份）。
- **正确做法**：元数据放**技能目录外**，例如 `~/.config/opencode/skills/.skill-zh-state/<name>.json`（状态目录固定为 `skills/` 下的点目录，与任何技能目录平级）。状态文件只记录三件事：已安装版本、属主文件清单（相对路径 + 内容哈希）、用户改动备份所在位置。技能目录内**只留技能本体**。
- **验收方式**：安装后对技能目录做文件集合快照，断言等于「源目录白名单集合」；状态目录存在且含该技能的 json；技能目录内不得出现任何以 `.` 开头的条目。

### 3. 不检测外部技能目录就安装，装完可能不生效

- **现象**：装成功、命令无报错，但模型用的是另一份同名技能（`~/.claude/skills/` 或项目里那份），或用户改的本包技能根本不生效。
- **根因**：安装器只认目标路径，不检查发现链（上游 `:315-405` 全程无检测）；而发现链里外部目录（`:185-203`）先扫、`skills.paths`/`skills.urls`（`:211-227`）后扫，后者覆盖前者——同名技能谁生效取决于扫描顺序，不看安装时间。上游更进一步：`archiveLegacySkill`（`:297-313`、`:391-397`）会直接把同级的 `skill-creator/` 改名归档，等于擅自动别人的目录。
- **正确做法**：安装前（启动钩子与 `skill_zh install` 共用同一套探测）按上面「事实底座一」的路径与开关**探测同名技能**；发现同名时**只提示、不擅自删改**——输出点名：哪几个目录存在同名技能、按扫描顺序**当前哪个生效**、建议怎么处理（见第 4 条的「真正能禁用」动作）。安装照常进行（写自己的目录本身无害），但绝不因检测到冲突就中止或改写别的目录。
- **验收方式**：在 `~/.claude/skills/<name>/SKILL.md`（或等价探测目录）放一份同名技能后跑安装，输出必须**点名该路径**并说明它当前覆盖了本包那份；断言探测目录内的文件集合、哈希与安装前一致（未被改动）。

### 4. 重命名目录不能禁用技能

- **现象**：按「重命名目录」的建议把 `skills/foo/` 改成 `skills/foo.disabled/`，技能**照样被发现、照样触发**；用户以为已禁用，实际在吃旧技能的行为。
- **根因**：文件名匹配是 `EXTERNAL_SKILL_PATTERN` / `OPENCODE_SKILL_PATTERN` 里的 `skills/**/SKILL.md`（`:21-25`）——`**` 匹配**任意层级**，目录叫什么都不影响「有没有 `SKILL.md`」这个判定条件。
- **正确做法**：错误文案与文档里**只能给真正生效的动作**：① 把 `SKILL.md` 改名为 `SKILL.md.disabled`（文件名不再匹配）；② 把整个目录移出任何 `skills/` 路径；③ 改 frontmatter `name`（让同名覆盖不成立，仅适用于「避免被覆盖」而非「禁用」）；④ 用 OpenCode 的权限 deny 规则拦掉；⑤ 用 `OPENCODE_DISABLE_EXTERNAL_SKILLS` / `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` 关掉整类外部来源。**不要**再出现「重命名目录即可禁用」这类说法。
- **验收方式**：对 `docs/`、`src/` 跑 `grep -n "重命名目录"`，每条命中所在的句子必须含「不能 / 无效 / 不要 / 不给 / 不出现 / 建议」之一（即只谈「不能这么做」或引用旧说法），作为**建议动作**出现即判失败；本文件与 [installation.md](../installation.md) 列出的禁用手段全部属于上述 5 类。

### 5. Windows / macOS 大小写不敏感：`SKILL.md` 就是 `skill.md`

- **现象**：清理与保护逻辑按精确名字比较时，`skill.md` 绕过保护被当成普通文件删除或覆盖；在 Linux 上测通、到 Windows 上出事。
- **根因**：大小写不敏感文件系统上 `skill.md` 与 `SKILL.md` 指向同一 inode，而精确匹配的集合（如 `:36-41`）对它不生效——上游已用 `RESERVED_ROOT_PATHS_LOWER`（`:43-57`）修过这一点。
- **正确做法**：**保留上游的 lower-case 保护**并扩大适用范围：受保护名集合与白名单条目比较一律先 `toLowerCase()`；判定「这是不是技能本体文件」也不区分大小写。
- **验收方式**：单测覆盖大小写变体——`SKILL.md` / `skill.md` / `Skill.MD` 三个变体都判为受保护、都命中白名单；构造一个只含 `skill.md` 的源目录，安装后目标侧同样落为技能本体而非被跳过或删除。

### 6. 同名升级覆盖用户改动

- **现象**：用户按自己的习惯改了装好的 `SKILL.md`（补了项目内的约定），升级插件后改动没了，只在同目录留下一个 `SKILL.md.user-backup` 且下次升级又被刷新覆盖。
- **根因**：上游升级策略是「有旧文件 → 先 `copyFileSync` 到 `.user-backup` → 再用包内版本覆盖」（`:348-363`），判定条件只有「版本变了」（`:337`），从不检查本地是否被改过。
- **正确做法**：`SKILL.md` 有本地改动时**默认不覆盖**：比对已安装版本的状态文件哈希与磁盘实际哈希，若不一致 → 跳过覆盖并提示两条出路（`skill_zh install --force` 强制用包内版本覆盖；或先自行备份再重试）。备份**永远写到状态目录**（第 2 条），文件名带时间戳，不落技能目录、不刷新旧备份。辅助文件（`agents/`、`references/`、`templates/`）维持「随包更新覆盖」。
- **验收方式**：装好后手工改 `SKILL.md` 的一个字 → 重跑安装（模拟升级）→ 断言技能目录内 `SKILL.md` 内容**仍是用户改过的版本**、输出提示 `--force`；加 `--force` 重跑 → 断言变为包内版本，且用户改动出现在状态目录的备份里（内容与改名前后字节一致）。

## 对实现的约束清单

可直接转成测试点；括号内是主要判据。

**拷贝与元数据**

- C1 白名单拷贝：只写 `SKILL.md`、`agents/**`、`references/**`、`templates/**`，其余条目跳过（第 1 条）。
- C2 白名单比较不区分大小写（第 5 条，与 C1 同一处实现）。
- C3 技能目录内不含安装器元数据：无点开头条目、无 `*.user-backup`（第 2 条）。
- C4 元数据只在状态目录 `~/.config/opencode/skills/.skill-zh-state/`，一技能一 json（第 2 条）。
- C5 状态文件记录「版本 + 属主文件相对路径与内容哈希 + 最近一次备份位置」三件事，不多不少（第 2、6 条）。

**发现链与禁用**

- C6 安装前探测同名技能：用户级 + 项目逐层的 `.claude/skills`、`.agents/skills`、OpenCode 配置目录、`skills.paths`（第 3 条）。
- C7 探测结果只提示不改写：探测目录内文件集合与哈希在安装前后一致（第 3 条）。
- C8 提示文案写明「按扫描顺序哪个生效」，且给出的处置动作属于第 4 条那 5 类；文案中不出现「重命名目录即可禁用」（第 3、4 条）。
- C9 尊重环境变量：`OPENCODE_DISABLE_EXTERNAL_SKILLS` 置位时不再把外部目录列为冲突源，`OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` 只影响 `.claude`（第 3 条）。

**升级**

- C10 本地改动保护：`SKILL.md` 磁盘哈希与状态文件记录不一致时默认跳过覆盖；`skill_zh install --force` 才覆盖（第 6 条）。
- C11 备份只写状态目录，文件名带时间戳，不刷新历史备份（第 6 条）。
- C12 只写自己的技能目录与状态目录：不触碰其它技能目录，不改名归档同级目录（第 3 条，对应上游 `:297-313`/`:391-397` 的反例）。
